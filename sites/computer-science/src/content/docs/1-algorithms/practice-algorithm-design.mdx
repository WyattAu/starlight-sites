## Intuition

**A toolbox of problem-solving strategies:** Algorithm design paradigms are like different tools in a workshop — divide-and-conquer is the saw (split the problem), dynamic programming is the memory palace (remember what you've solved), and backtracking is the trial-and-error approach (try, undo, try again).

**Why it matters:** Knowing which paradigm fits a problem is the first step to solving it efficiently. The wrong paradigm leads to exponential time; the right one can make the difference between feasible and infeasible.

**The key insight:** Dynamic programming works when subproblems overlap — if you're solving the same subproblem twice, remember the answer instead of recomputing it. This transforms exponential algorithms into polynomial ones.

## Common Mistakes

**Assuming greedy algorithms always give optimal solutions:** Greedy works for some problems (activity selection, Huffman) but fails for others (0/1 knapsack, TSP). Always verify the greedy choice property.

**Forgetting that dynamic programming requires optimal substructure:** DP works when the optimal solution contains optimal solutions to subproblems. Not all problems have this property.

**Confusing divide-and-conquer with dynamic programming:** Divide-and-conquer splits problems into independent subproblems. DP handles overlapping subproblems with memoisation. Don't confuse the two paradigms.
