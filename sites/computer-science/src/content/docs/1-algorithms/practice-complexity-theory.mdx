## Complexity Theory -- Practice Problems

10 MCQ questions covering Big-O notation, complexity classes (P, NP, NP-complete), polynomial-time
reductions, Cook\'s theorem, and approximation algorithms. Select an option to check your answer.

## Intuition

**Sorting problems into difficulty bins:** Complexity classes are like sorting problems into difficulty bins — P problems are easy (solvable quickly), NP problems are easy to check (even if hard to solve), and NP-complete problems are the hardest in NP. NP-hard problems are at least as hard as NP-complete.

**Why it matters:** Complexity theory tells you when to keep looking for a fast algorithm and when to accept that one probably doesn't exist. It guides real engineering decisions — from cryptography (we rely on factoring being hard) to AI planning (we use approximations for NP-hard problems).

**The key insight:** NP doesn't mean "hard to solve" — it means "easy to verify." The million-dollar question is whether P = NP, which would mean every easily verifiable problem is also easily solvable.

## Approximation Algorithms and Hardness

<PracticeProblem client:only="solid-js" question={"What approximation ratio does the greedy algorithm achieve for the Vertex Cover problem?&quot; options={[ '2-approximation: $|C| \\leq 2 \\cdot |OPT|$', '$\\ln(n)$-approximation', '3/2-approximation', 'No constant approximation ratio is possible unless P = NP', ]} correctAnswer={0} explanation=&quot;The greedy algorithm picks an arbitrary edge, adds both endpoints to the cover, and removes all incident edges. <PracticeProblem client:only="solid-js" question={"What is the key consequence of the PCP Theorem (1992) for the Max-3SAT problem?&quot; options={[ 'Max-3SAT cannot be approximated beyond $7/8 + \\epsilon$ unless P = NP', 'Max-3SAT can be solved exactly in polynomial time', 'Max-3SAT has a PTAS (polynomial-time approximation scheme)', 'Max-3SAT cannot be approximated within any constant factor', ]} correctAnswer={0} explanation=&quot;The PCP Theorem states that every problem in NP has a probabilistically checkable proof verifiable by reading a constant number of bits. <PracticeProblem client:only="solid-js" question={"Which of the following correctly describes the relationship $P \\subseteq NP \\subseteq PSPACE \\subseteq EXP$?&quot; options={[ 'Each class is contained within the next, and all inclusions are known to be strict except possibly P = NP', 'All classes are equal', 'Only P $\\subseteq$ NP is known; the other inclusions are conjectured', 'NP = PSPACE but P $\\neq$ PSPACE', ]} correctAnswer={0} explanation=&quot;The chain $P \\subseteq NP \\subseteq PSPACE \\subseteq EXP$ is well-established. $P \\subseteq NP$ because a deterministic TM is a special case of a nondeterministic one. $NP \\subseteq PSPACE$ because polynomial space suffices to try all certificates. $PSPACE \\subseteq EXP$ because with exponential time, one can enumerate all possible configurations. ## Additional Complexity Theory Questions

<PracticeProblem client:only="solid-js" question={"The Space Hierarchy Theorem states that for constructible functions $f(n)$, there exists a language decidable in $O(f(n))$ space but not in $o(f(n))$ space. Which of the following is a direct consequence?&quot; options={[ 'There exist problems solvable in $O(n^2)$ space but not in $O(n)$ space', 'P = NP', 'PSPACE = EXP', 'Every problem in NP is solvable in polynomial space', ]} correctAnswer={0} explanation=&quot;The Space Hierarchy Theorem guarantees strict separations within space complexity classes. This does not resolve P vs NP (which concerns time, not space) but does establish that $\\text{SPACE}(f(n)) \\subsetneq \\text{SPACE}(g(n))$ when $f(n) = o(g(n))$ and $g$ is constructible."} difficulty="medium"  />

<PracticeProblem client:only="solid-js" question={"What is the significance of the Ladner theorem for the structure of NP?&quot; options={[ 'If P $\\neq$ NP, then there exist NP-intermediate problems that are neither in P nor NP-complete', 'NP is always equal to P', 'All NP problems are either in P or NP-complete with no gap', 'NP-intermediate problems exist only if P = NP', ]} correctAnswer={0} explanation=&quot;Ladner's theorem (1975) shows that if P $\\neq$ NP, then there exist languages in NP that are neither in P nor NP-complete. These NP-intermediate problems (e.g., graph isomorphism, factoring) sit strictly between P and NP-complete. If P = NP, the distinction collapses and all problems in NP become solvable in polynomial time."} difficulty="medium"  />

<PracticeProblem client:only="solid-js" question={"The polynomial hierarchy (PH) is a generalisation of NP. If PH collapses (e.g., $\\Sigma_2^P = \\Sigma_1^P$), it would imply $P = NP$. The hierarchy is believed to be infinite."} difficulty="hard"  />

<PracticeProblem client:only="solid-js" question={"Which of the following problems is known to be in coNP but not known to be in P?&quot; options={[ 'The complement of SAT (UNSAT)', 'Hamiltonian Cycle', 'Subset Sum', 'Graph Colouring (3-colouring)', ]} correctAnswer={0} explanation=&quot;UNSAT (the complement of SAT) is in coNP because a satisfying assignment can be checked and rejected in polynomial time. <PracticeProblem client:only="solid-js" question={"What does Savitch's theorem state about the relationship between deterministic and nondeterministic space?&quot; options={[ '$\\text{NSPACE}(s(n)) \\subseteq \\text{DSPACE}(s(n)^2)$ for $s(n) \\geq \\log n$', '$\\text{NSPACE}(s(n)) = \\text{DSPACE}(s(n))$ for all $s(n)$', '$\\text{NSPACE}(s(n)) \\subseteq \\text{DSPACE}(2^{s(n)})$', '$\\text{NSPACE}(s(n)) \\subseteq \\text{DSPACE}(s(n) \\log s(n))$', ]} correctAnswer={0} explanation=&quot;Savitch's theorem (1970) proves that nondeterministic space is at most the square of deterministic space: $\\text{NSPACE}(s(n)) \\subseteq \\text{DSPACE}(s(n)^2)$. ## Common Mistakes

**Confusing decidability with complexity:** Decidable means a Turing machine halts on all inputs. Complexity classes (P, NP) describe how efficiently problems are solved. Don't confuse the two concepts.

**Assuming NP-complete means unsolvable:** NP-complete problems can be solved — just not in polynomial time (unless P = NP). They're hard but not impossible.

**Forgetting that reductions go the wrong way for hardness:** To show problem X is hard, reduce a known hard problem TO X. Don't reduce X to something else — that shows X is easy.
