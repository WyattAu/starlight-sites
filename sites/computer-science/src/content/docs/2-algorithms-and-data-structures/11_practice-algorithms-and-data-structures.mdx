## Intuition

**The building blocks of efficient software:** Algorithms and data structures are like the building blocks of efficient software — algorithms are the blueprints for solving problems, and data structures are the materials you build with. The right combination makes your software fast; the wrong one makes it slow.

**Why it matters:** Every software application uses algorithms and data structures, whether you know it or not. Understanding them lets you write code that scales — handling thousands of users instead of crashing at ten.

**The key insight:** Amortised analysis reveals hidden efficiency — a dynamic array's occasional expensive resize is cheap when averaged over many insertions, giving O(1) amortised cost per operation.

## Common Mistakes

**Confusing max-heaps with min-heaps:** Max-heaps have the largest element at the root. Min-heaps have the smallest. Don't assume heap operations always extract the maximum.

**Forgetting that hash table worst-case is O(n):** Average case is O(1) with good hashing. But if all keys collide, performance degrades to O(n). Always consider worst-case.

**Mixing up BFS with DFS traversal order:** BFS explores level by level (queue). DFS explores depth-first (stack/recursion). They visit nodes in different orders.
