## Algorithms and Data Structures -- Practice Problems

## Intuition

**The art of efficient computation:** Algorithm design is like chess strategy — you need to think ahead (plan your approach), recognise patterns (identify the right paradigm), and know when to trade optimality for speed (heuristics vs. exact solutions).

**Why it matters:** The difference between a good and bad algorithm can be the difference between a solution that takes milliseconds and one that takes years. Understanding these concepts lets you make informed choices about code efficiency.

**The key insight:** Comparison-based sorting has a fundamental limit of O(n log n) — no clever algorithm can beat this because of the information-theoretic lower bound. To go faster, you need to use non-comparison methods like radix sort.

<PracticeProblem client:only="solid-js" question={"Which of the following is the correct asymptotic lower bound for comparison-based sorting?&quot; options={['$\\Omega(n \\log n)$', '$\\Omega(n^2)$', '$\\Omega(n)$', '$\\Omega(\\log n)$']} correctAnswer={0} explanation=&quot;The comparison-based sorting lower bound of $\\Omega(n \\log n)$ arises from decision tree analysis. A comparison-based sort on $n$ elements must distinguish among $n!$ possible permutations. A binary decision tree of height $h$ has at most $2^h$ leaves, so we need $2^h \\geq n!$, giving $h \\geq \\log_2(n!) = \\Omega(n \\log n)$. Algorithms like radix sort bypass this bound by not using comparisons."} difficulty="medium"  />

## Trees and Hash Tables

<PracticeProblem client:only="solid-js" question={"What is the maximum number of nodes at depth $d$ (root at depth 0) in a binary tree?&quot; options={['$2^d$', '$2^{d+1}$', '$2^d - 1$', '$d$']} correctAnswer={0} explanation=&quot;In a binary tree, each node can have at most 2 children. At depth 0 there is at most 1 node, at depth 1 at most 2, at depth 2 at most 4, and so on. By induction, the maximum number of nodes at depth $d$ is $2^d$. A complete binary tree achieves this maximum at every level. A perfect binary tree of height $h$ has $2^{h+1} - 1$ total nodes."} difficulty="medium"  />

<PracticeProblem client:only="solid-js" question={"In an AVL tree, after inserting a node causes an imbalance at some ancestor, what is the worst-case height of an AVL tree with $n$ nodes?&quot; options={['$O(\\log n)$', '$O(n)$', '$O(\\sqrt{n})$', '$O(n \\log n)$']} correctAnswer={0} explanation=&quot;An AVL tree maintains the balance invariant: for every node, the heights of the left and right subtrees differ by at most 1. This constraint guarantees $h = O(\\log n)$. Specifically, the minimum number of nodes in an AVL tree of height $h$ is $F_{h+2} - 1$ (related to Fibonacci numbers), yielding $h \\leq 1.44 \\log_2(n+2) - 0.328$. Rotations during insertion restore balance in $O(1)$ time."} difficulty="medium"  />

<PracticeProblem client:only="solid-js" question={"A hash table uses chaining with a load factor $\\alpha = n/m$. Under uniform hashing, the expected chain length at any bucket is $\\alpha = n/m$. Therefore, the expected time for an unsuccessful search is $O(\\alpha)$. For successful search, the expected time is $O(1 + \\alpha/2)$. When $\\alpha$ is kept constant (e.g., by resizing), both operations are $O(1)$ expected."} difficulty="medium"  />

<PracticeProblem client:only="solid-js" question={"In a red-black tree, which property ensures that the longest path from root to leaf is at most twice the shortest path?&quot; options={[ 'Every node is either red or black, and no two consecutive red nodes appear on any path', 'The root is always black', 'Every leaf (NIL) is black', 'All paths from a node to its descendant NIL nodes contain the same number of black nodes', ]} correctAnswer={0} explanation={`The key property is that no red node can have a red child (the &quot;no red-red&quot; constraint). ## Complexity Analysis and Advanced Topics

<PracticeProblem client:only="solid-js" question={"What is the time complexity of finding the $k$-th smallest element in an unsorted array using the randomized quickselect algorithm?&quot; options={['$O(n)$ expected', '$O(n \\log n)$ worst case', '$O(n^2)$ expected', '$O(k \\log n)$']} correctAnswer={0} explanation=&quot;Randomized quickselect has $O(n)$ expected time. Like quicksort, it partitions around a pivot but recurses into only one side. The expected recurrence is $T(n) = T(n/2) + O(n)$, solving to $O(n)$. The worst case is $O(n^2)$ (same degenerate case as quicksort), but the median-of-medians variant guarantees $O(n)$ worst case at the cost of a larger constant factor."} difficulty="hard"  />

<PracticeProblem client:only="solid-js" question={"What is the amortized time complexity of inserting $n$ elements into a dynamic array that doubles in size when full?&quot; options={[ '$O(1)$ per insertion', '$O(n)$ per insertion', '$O(\\log n)$ per insertion', '$O(n^2)$ total', ]} correctAnswer={0} explanation=&quot;Although individual insertions may trigger an $O(n)$ resize, the amortized cost is $O(1)$. When the array doubles from size $m$ to $2m$, the copy costs $O(m)$, but this cost is spread across the $m$ insertions since the last resize. Each of those $m$ insertions is charged $O(1)$ for the copy plus $O(1)$ for the insertion itself, giving $O(1)$ amortized. The total cost for $n$ insertions is $O(n)$."} difficulty="medium"  />

<PracticeProblem client:only="solid-js" question={"What data structure would you use to efficiently maintain the running median of a stream of numbers, and what is its time complexity per insertion?&quot; options={[ 'Two heaps (a max-heap for the lower half and a min-heap for the upper half); $O(\\log n)$ per insertion', 'A balanced BST; $O(\\log n)$ per insertion', 'An unsorted array; $O(1)$ per insertion but $O(n)$ to find the median', 'A hash table; $O(1)$ per insertion and $O(1)$ to find the median', ]} correctAnswer={0} explanation=&quot;Maintain a max-heap of the smaller half and a min-heap of the larger half.
