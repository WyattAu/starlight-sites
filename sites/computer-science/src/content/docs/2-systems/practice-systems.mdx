## Intuition

**The plumbing of modern computing:** Systems topics are like the plumbing of a building — you don't see them, but when they fail, everything stops. Databases store the water, networks are the pipes, and the OS is the plumber keeping it all flowing.

**Why it matters:** Systems knowledge bridges theory and practice — it explains why databases crash, why networks slow down, and how operating systems keep everything running. This is the knowledge that separates junior from senior engineers.

**The key insight:** Most system failures come from incorrect assumptions — assuming the network is reliable, assuming hardware never fails, assuming all clients behave nicely. Good systems design expects failure and plans for it.

## Common Mistakes

**Confusing virtual memory with virtual machines:** Virtual memory is an OS technique for using disk as extended RAM. Virtual machines are emulated computers. They're different concepts.

**Assuming more RAM always improves performance:** More RAM helps if the system is memory-bound. If the bottleneck is CPU or I/O, adding RAM won't help.

**Mixing up pre-emptive with cooperative multitasking:** Pre-emptive multitasking forces context switches (OS controls scheduling). Cooperative multitasking relies on processes voluntarily yielding. Don't assume all systems are pre-emptive.
