## Database Theory and Distributed Systems

<PracticeProblem client:only="solid-js" question={"Which normal form eliminates transitive dependencies by ensuring that every non-prime attribute is non-transitively dependent on the primary key?&quot; options={[ 'Third Normal Form (3NF)', 'Second Normal Form (2NF)', 'Boyce-Codd Normal Form (BCNF)', 'Fourth Normal Form (4NF)', ]} correctAnswer={0} explanation=&quot;3NF requires that for every functional dependency $X \\to A$: either $X$ is a superkey, or $A$ is a prime attribute. This eliminates transitive dependencies where $A$ depends on $X$ through some intermediate non-key attribute. BCNF is stricter, requiring $X$ to be a superkey for every non-trivial FD $X \\to A$."} difficulty="easy"  />

<PracticeProblem client:only="solid-js" question={"In the CAP theorem, a distributed system that remains available and partition-tolerant (AP) must sacrifice:&quot; options={['Strong consistency', 'Durability', 'Fault tolerance', 'Scalability']} correctAnswer={0} explanation=&quot;The CAP theorem states that a distributed system can guarantee at most two of: Consistency (all nodes see the same data), Availability (every request receives a response), and Partition tolerance (system continues despite network partitions). An AP system (e.g., Cassandra, DynamoDB in eventual consistency mode) remains available during partitions but sacrifices strong consistency, offering eventual consistency instead."} difficulty="easy"  />

<PracticeProblem client:only="solid-js" question={"In Raft consensus, a leader is elected using a randomized election timeout. What is the primary purpose of this randomisation?&quot; options={[ 'To prevent split votes when multiple followers become candidates simultaneously', 'To balance load across followers', 'To ensure liveness by bounding election time', 'To reduce the number of log entries per term', ]} correctAnswer={0} explanation=&quot;When a leader fails, all followers that do not receive heartbeats within their election timeout become candidates. If all followers had the same fixed timeout, they would all start elections simultaneously and split votes (no candidate gets majority). Randomised timeouts stagger the start times, making it very likely that only one candidate wins and becomes the leader."} difficulty="medium"  />

<PracticeProblem client:only="solid-js" question={"Which ACID property guarantees that a transaction either completes entirely or has no effect at all, even after a system crash?&quot; options={['Atomicity', 'Consistency', 'Isolation', 'Durability']} correctAnswer={0} explanation=&quot;Atomicity means a transaction is an indivisible unit of work -- either all operations in the transaction commit, or none do. This is implemented using write-ahead logging (WAL) and undo logs: changes are recorded in a log before being applied, and if the system crashes before the transaction commits, the undo log is used to roll back all partial changes."} difficulty="medium"  />

## Networking and Operating Systems

<PracticeProblem client:only="solid-js" question={"At which layer of the OSI model does a router primarily operate?&quot; options={[ 'Network Layer (Layer 3)', 'Data Link Layer (Layer 2)', 'Transport Layer (Layer 4)', 'Physical Layer (Layer 1)', ]} correctAnswer={0} explanation=&quot;Routers operate at the Network Layer (Layer 3) of the OSI model. ## Virtual Memory and File Systems

<PracticeProblem client:only="solid-js" question={"What is the primary advantage of multi-level page tables over a single-level page table?&quot; options={[ 'They reduce the amount of physical memory required to store the page table by only allocating page table pages for valid address ranges', 'They reduce the TLB miss rate', 'They eliminate the need for a TLB entirely', 'They provide faster address translation', ]} correctAnswer={0} explanation=&quot;A single-level page table for a 48-bit address space with 4 KB pages requires $2^{36}$ entries (~2 TB). Multi-level page tables use a tree structure where only the pages corresponding to valid address ranges need to be allocated in physical memory. The trade-off is extra memory accesses per translation (one per level), mitigated by TLB caching."} difficulty="medium"  />
<PracticeProblem client:only="solid-js" question={"In a Unix-like file system, an inode stores all of the following EXCEPT:&quot; options={[ 'The file name', 'File size and timestamps', 'Direct and indirect block pointers', 'Owner permissions (UID/GID) and mode', ]} correctAnswer={0} explanation=&quot;Inodes store file metadata (size, timestamps, ownership, permissions) and block pointers (direct, single/double/triple indirect), but NOT the file name. File names are stored in directory entries, which map names to inode numbers. This separation allows multiple hard links (names) to point to the same inode, and renaming a file only requires updating the directory entry."} difficulty="hard"  />

## Common Mistakes

**Confusing virtual memory with virtual machines:** Virtual memory is an OS technique for using disk as extended RAM. Virtual machines are emulated computers. They're different concepts.

**Assuming more RAM always improves performance:** More RAM helps if the system is memory-bound. If the bottleneck is CPU or I/O, adding RAM won't help.

**Mixing up pre-emptive with cooperative multitasking:** Pre-emptive multitasking forces context switches (OS controls scheduling). Cooperative multitasking relies on processes voluntarily yielding. Don't assume all systems are pre-emptive.
