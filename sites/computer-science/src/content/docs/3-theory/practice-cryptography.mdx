## Intuition

**A lock and key system for digital messages:** Cryptography is like a postal security system — symmetric encryption is a shared lock (both sender and key have the same key), asymmetric encryption is a mailbox (anyone can drop mail in, only you can open it), and hash functions are tamper-evident seals.

**Why it matters:** Every online transaction, password login, and secure message relies on cryptography. Understanding it explains why HTTPS matters, how Bitcoin works, and why quantum computers threaten current security.

**The key insight:** Security depends on mathematical hardness assumptions — RSA relies on factoring being hard, Diffie-Hellman on discrete logarithms — and when those assumptions break, so does the security.

<PracticeProblem client:only="solid-js" question={"In AES with a 128-bit key, how many rounds are performed and what operations occur in each round (except the last)?&quot; options={[ '10 rounds: SubBytes, ShiftRows, MixColumns, AddRoundKey; last round omits MixColumns', '16 rounds: all four operations in every round', '10 rounds: only SubBytes and AddRoundKey', '8 rounds: SubBytes, ShiftRows, MixColumns, AddRoundKey, and KeyExpansion', ]} correctAnswer={0} explanation=&quot;AES-128 has 10 rounds. <PracticeProblem client:only="solid-js" question={"The One-Time Pad provides perfect secrecy (information-theoretic security). <PracticeProblem client:only="solid-js" question={"In CTR mode, the keystream is generated by encrypting a counter value with the block cipher. ## Asymmetric Encryption, Hash Functions, and Key Exchange

<PracticeProblem client:only="solid-js" question={"In RSA, given public key $(e, n)$ and private key $(d, n)$ where $n = pq$, the correctness of decryption relies on which theorem?&quot; options={[ &quot;Euler\'s theorem: $m^{ed} \\equiv m \\pmod{n}$ when $ed \\equiv 1 \\pmod{\\varphi(n)}$&quot;, &quot;Fermat\'s Last Theorem&quot;, 'The Chinese Remainder Theorem for key generation only', &quot;Bayes' theorem for probabilistic verification&quot;, ]} correctAnswer={0} explanation=&quot;RSA key generation: choose primes $p, q$, compute $n = pq$, $\\varphi(n) = (p-1)(q-1)$, choose $e$ coprime to $\\varphi(n)$, compute $d = e^{-1} \\bmod \\varphi(n)$. Encryption: $c = m^e \\bmod n$. Decryption: $m = c^d \\bmod n = m^{ed} \\bmod n$. Since $ed = k\\varphi(n)+1$, by Euler\'s theorem: $m^{ed} = m \\cdot (m^{\\varphi(n)})^k \\equiv m \\pmod{n}$."} difficulty="medium"  />

<PracticeProblem client:only="solid-js" question={"The birthday attack on hash functions exploits the fact that a collision can be found in approximately how many hash evaluations for an $n$-bit hash?&quot; options={[ '$O(2^{n/2})$ evaluations', '$O(2^n)$ evaluations', '$O(n)$ evaluations', '$O(2^{2n})$ evaluations', ]} correctAnswer={0} explanation=&quot;The birthday paradox: with $\\sqrt{2^n} = 2^{n/2}$ random hash outputs, the probability of a collision is approximately 50%. For SHA-256 ($n=256$), this is $2^{128}$ evaluations. This is why SHA-1 (160-bit) was broken (collision found in $\\sim 2^{80}$ operations) and why 256-bit hashes are recommended for collision resistance."} difficulty="easy"  />

<PracticeProblem client:only="solid-js" question={"Diffie-Hellman key exchange establishes a shared secret using the group $\\mathbb{Z}_p^*$. What computational problem provides its security?&quot; options={[ 'The Discrete Logarithm Problem (DLP): given $g^a \\bmod p$, finding $a$ is computationally hard', 'Integer factorization of $p$', 'The subset sum problem', 'The knapsack problem', ]} correctAnswer={0} explanation=&quot;In DH, Alice sends $A = g^a \\bmod p$, Bob sends $B = g^b \\bmod p$. Shared secret: $s = B^a = g^{ab} = A^b \\bmod p$. An eavesdropper sees $g$, $p$, $A$, $B$ but needs $a$ or $b$ to compute $s$. Finding $a$ from $A = g^a \\bmod p$ is the DLP, believed hard for appropriately chosen primes. Ephemeral DH (DHE) provides forward secrecy."} difficulty="medium"  />

<PracticeProblem client:only="solid-js" question={"Which post-quantum cryptographic algorithm was standardized by NIST in 2024 as a lattice-based key encapsulation mechanism?&quot; options={[ 'ML-KEM (Module-Lattice Key Encapsulation Mechanism)', 'RSA-4096 with doubled key size', 'AES-512', 'SHA-512', ]} correctAnswer={0} explanation=&quot;NIST selected ML-KEM (based on the Module Learning With Errors problem) to replace Diffie-Hellman for key exchange against quantum attacks. Shor\'s algorithm can break RSA, ECC, and DH in polynomial time on a quantum computer. ML-KEM provides quantum-resistant security. ML-DSA (lattice-based) replaces RSA/ECDSA for signatures."} difficulty="hard"  />

<PracticeProblem client:only="solid-js" question={"What is the primary security issue with textbook RSA signatures ($\\sigma = m^d \\bmod n$) without padding?&quot; options={[ 'Vulnerable to existential forgeries and chosen-message attacks (e.g., Bleichenbacher)', 'The signature is too long for practical use', 'Decryption is too slow', 'It only works for short messages', ]} correctAnswer={0} explanation=&quot;Textbook RSA signatures sign the raw message hash: $\\sigma = H(m)^d \\bmod n$. Without proper padding (PSS - Probabilistic Signature Scheme), this is vulnerable to existential forgeries, multiplicative properties ($\\sigma_1 \\cdot \\sigma_2$ signs $m_1 \\cdot m_2$), and Bleichenbacher-style attacks. Always use PSS padding for RSA signatures."} difficulty="hard"  />

<PracticeProblem client:only="solid-js" question={"What does forward secrecy in a key exchange protocol guarantee?&quot; options={[ 'If long-term keys are compromised, past session keys remain secure', 'Future sessions are protected against quantum attacks', 'The protocol never needs to exchange new keys', 'All messages are encrypted with the same key indefinitely', ]} correctAnswer={0} explanation=&quot;Forward secrecy (perfect forward secrecy) means that compromising a long-term private key does not allow decryption of past session communications. This is achieved by using ephemeral key exchange (DHE or ECDHE) where each session generates fresh key pairs that are discarded afterward. Static DH does not provide forward secrecy."} difficulty="easy"  />

## Additional Cryptography Questions

<PracticeProblem client:only="solid-js" question={"In elliptic curve cryptography (ECC), what computational problem provides the security analogous to the discrete logarithm problem in finite fields?&quot; options={[ 'The Elliptic Curve Discrete Logarithm Problem (ECDLP): given points $P$ and $Q = kP$ on the curve, finding $k$ is hard', 'The integer factorisation problem', 'The subset sum problem', 'The lattice shortest vector problem', ]} correctAnswer={0} explanation=&quot;ECC defines a group structure on the points of an elliptic curve over a finite field under point addition. The ECDLP asks: given $P$ and $Q = kP$ (scalar multiplication), find $k$. The best known classical algorithms for ECDLP run in $O(\\sqrt{n})$ time (where $n$ is the group order), compared to sub-exponential algorithms for integer factorisation and DLP in finite fields. This allows ECC to use smaller key sizes (256-bit ECC ≈ 3072-bit RSA)."} difficulty="medium"  />

<PracticeProblem client:only="solid-js" question={"What is a cryptographic hash function and which three properties define its security?&quot; options={[ 'Pre-image resistance, second pre-image resistance, and collision resistance', 'Confusion, diffusion, and avalanche effect', 'Symmetry, transitivity, and commutativity', 'Key generation, encryption, and decryption', ]} correctAnswer={0} explanation=&quot;Pre-image resistance: given $h$, it is hard to find any $m$ such that $H(m) = h$. Second pre-image resistance: given $m_1$, it is hard to find $m_2 \\neq m_1$ such that $H(m_1) = H(m_2)$. Collision resistance: it is hard to find any pair $m_1 \\neq m_2$ with $H(m_1) = H(m_2)$. Collision resistance implies second pre-image resistance. SHA-256 provides 128-bit collision resistance (requires $\\sim 2^{128}$ operations)."} difficulty="easy"  />

<PracticeProblem client:only="solid-js" question={"In the Merkle--Damgard construction used by SHA-1 and SHA-256, how is collision resistance ensured?&quot; options={[ 'By applying a compression function iteratively to blocks, where a collision in the hash implies a collision in the compression function', 'By encrypting the input with a secret key before hashing', 'By using a random salt for each hash computation', 'By truncating the output to a fixed length', ]} correctAnswer={0} explanation=&quot;Merkle--Damgard processes the input in fixed-size blocks using a collision-resistant compression function $f$. The hash of message $M$ is $H(M) = f(f(f(IV, M_1), M_2), \\ldots, M_k)$ with appropriate padding. A collision in $H$ would imply a collision in $f$ (by an induction argument on the chain). This reduces the security proof to the compression function. SHA-256 uses the Davies--Meyer construction for its compression function."} difficulty="medium"  />

<PracticeProblem client:only="solid-js" question={"What is the key difference between the CBC-MAC and HMAC for message authentication?&quot; options={[ 'CBC-MAC is vulnerable to length extension attacks; HMAC uses a nested hash construction that resists them', 'CBC-MAC provides confidentiality while HMAC does not', 'HMAC is faster than CBC-MAC for all message lengths', 'CBC-MAC requires a secret key while HMAC does not', ]} correctAnswer={0} explanation=&quot;CBC-MAC applies AES-CBC to the message and outputs the final ciphertext block as the tag. It is secure for fixed-length messages but vulnerable to length extension and other attacks on variable-length messages. HMAC uses $H(K \\oplus opad \\;\\|\\; H(K \\oplus ipad \\;\\|\\; M))$, which provides provable security based on the hash function's properties. HMAC resists length extension because the inner hash output is not exposed to the attacker."} difficulty="medium"  />

<PracticeProblem client:only="solid-js" question={"What is the role of a random nonce in the RSA-OAEP encryption scheme, and why is textbook RSA (without padding) insecure?&quot; options={[ 'OAEP uses randomness to prevent deterministic encryption, ensuring that the same plaintext produces different ciphertexts each time; textbook RSA is deterministic and vulnerable to chosen-plaintext attacks', 'The nonce in OAEP is used for key derivation; textbook RSA cannot encrypt at all', 'OAEP uses randomness to speed up encryption; textbook RSA is slower', 'The nonce prevents quantum attacks; textbook RSA is quantum-vulnerable', ]} correctAnswer={0} explanation=&quot;Textbook RSA is deterministic: $c = m^e \\bmod n$ always produces the same ciphertext for the same plaintext. This enables chosen-plaintext attacks, partial information leakage, and algebraic manipulations. RSA-OAEP (Optimal Asymmetric Encryption Padding) uses a Feistel network with randomness to create a probabilistic encryption scheme. The same plaintext produces a different ciphertext each time, providing IND-CPA security under the RSA assumption."} difficulty="hard"  />

## Common Mistakes

**Confusing encryption with signing:** Encryption protects confidentiality (only recipient can read). Signing provides authentication and integrity (sender can't deny sending). Don't use them interchangeably.

**Assuming longer keys are always better:** Security depends on the algorithm, not just key length. A 1024-bit RSA key is less secure than a 256-bit ECC key. Don't assume key length alone determines security.

**Forgetting that hash functions are not encryption:** Hash functions produce fixed-size digests from arbitrary input. They're one-way (can't recover input). Don't use them for encryption.
