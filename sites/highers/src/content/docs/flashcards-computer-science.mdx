## Intuition

Computer science is about solving problems systematically — breaking complex tasks into algorithms that machines can execute. Hardware provides the physical foundation (CPU, memory, storage), while software provides the instructions. Databases organise data efficiently, networks connect systems together, and algorithms determine how quickly problems get solved. Understanding time complexity (Big O notation) tells you whether your solution scales or collapses under load.

## Common Pitfalls

- **Binary/hex conversion errors**: Forgetting that hex is base-16 (digits 0-9, A-F) and mixing up the direction of conversion — practice with small numbers first.
- **Stack vs heap confusion**: The stack stores local variables and function calls (fast, limited size), while the heap stores dynamically allocated memory (slower, larger) — confusing the two leads to memory leaks or stack overflow.
- **SQL injection**: Building SQL queries by concatenating user input directly — always use parameterised queries to prevent attackers from injecting malicious SQL commands.
- **Big O notation errors**: Confusing O(n) with O(n²) — a nested loop is O(n²), not O(2n). Count the number of operations relative to input size.
- **Network layer confusion**: Mixing up MAC addresses (Data Link layer, hardware) with IP addresses (Network layer, logical) — they operate at different OSI layers and serve different purposes.

## Study Tips

- **Trace algorithms by hand:** For sorting and searching algorithms, trace through with a small example (5-6 elements). This reveals the actual number of operations and helps you understand time complexity.
- **Build truth tables for logic circuits:** For Boolean algebra questions, construct the full truth table first, then derive the simplified expression. This prevents simplification errors.
- **Practise SQL queries against real databases:** Use SQLite or an online SQL editor to test queries. Understanding JOIN types requires seeing actual result sets, not just reading about them.
- **Convert between number systems regularly:** Practise converting between binary, decimal, hexadecimal, and octal. Speed with these conversions comes from repeated practice.
- **Draw network diagrams:** For networking questions, sketch the network topology and label IP addresses, subnet masks, and default gateways. Visual diagrams prevent configuration errors.
- **Practise pseudo-code writing:** SQA exams may require writing pseudo-code. Practise expressing algorithms in a clear, structured format that examiners can follow.
- **Study data representation:** Understand how integers, floating-point numbers, text, and images are represented in binary. Two's complement, IEEE 754, and ASCII/Unicode are fundamental.
