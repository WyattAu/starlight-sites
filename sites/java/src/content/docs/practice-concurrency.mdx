## Concurrency Practice

## Exercise 1: Producer-Consumer

**Problem:**
Implement a producer-consumer pattern using a shared bounded buffer with threads.

**Hint:** Use `wait()` and `notifyAll()` or a `BlockingQueue` for synchronization.

```java
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.BlockingQueue;

class Producer implements Runnable {
    private final BlockingQueue<Integer> buffer;
    private final int itemsToProduce;

    public Producer(BlockingQueue<Integer> buffer, int itemsToProduce) {
        this.buffer = buffer;
        this.itemsToProduce = itemsToProduce;
    }

    @Override
    public void run() {
        try {
            for (int i = 0; i < itemsToProduce; i++) {
                buffer.put(i);
                System.out.println("Produced: " + i);
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

class Consumer implements Runnable {
    private final BlockingQueue<Integer> buffer;
    private final int itemsToConsume;

    public Consumer(BlockingQueue<Integer> buffer, int itemsToConsume) {
        this.buffer = buffer;
        this.itemsToConsume = itemsToConsume;
    }

    @Override
    public void run() {
        try {
            for (int i = 0; i < itemsToConsume; i++) {
                int item = buffer.take();
                System.out.println("Consumed: " + item);
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

class ProducerConsumerDemo {
    public static void main(String[] args) throws InterruptedException {
        BlockingQueue<Integer> buffer = new ArrayBlockingQueue<>(5);
        Thread producer = new Thread(new Producer(buffer, 10));
        Thread consumer = new Thread(new Consumer(buffer, 10));
        producer.start();
        consumer.start();
        producer.join();
        consumer.join();
    }
}
```

## Exercise 2: Thread-Safe Singleton

**Problem:**
Implement a thread-safe singleton using double-checked locking and a Bill Pugh holder pattern.

**Hint:** Use `volatile` field with `synchronized` block, or a static inner class holder.

```java
class DCLSingleton {
    private static volatile DCLSingleton instance;

    private DCLSingleton() {}

    public static DCLSingleton getInstance() {
        if (instance == null) {
            synchronized (DCLSingleton.class) {
                if (instance == null) {
                    instance = new DCLSingleton();
                }
            }
        }
        return instance;
    }
}

class HolderSingleton {
    private HolderSingleton() {}

    private static class Holder {
        private static final HolderSingleton INSTANCE = new HolderSingleton();
    }

    public static HolderSingleton getInstance() {
        return Holder.INSTANCE;
    }
}
```

## Exercise 3: Read-Write Lock

**Problem:**
Implement a read-write lock using `ReentrantReadWriteLock` for a thread-safe cache.

**Hint:** Acquire a read lock for get operations and a write lock for put operations.

```java
import java.util.HashMap;
import java.util.Map;
import java.util.concurrent.locks.ReadWriteLock;
import java.util.concurrent.locks.ReentrantReadWriteLock;

class ThreadSafeCache<K, V> {
    private final Map<K, V> map = new HashMap<>();
    private final ReadWriteLock lock = new ReentrantReadWriteLock();

    public V get(K key) {
        lock.readLock().lock();
        try {
            return map.get(key);
        } finally {
            lock.readLock().unlock();
        }
    }

    public void put(K key, V value) {
        lock.writeLock().lock();
        try {
            map.put(key, value);
        } finally {
            lock.writeLock().unlock();
        }
    }

    public V getOrDefault(K key, V defaultValue) {
        lock.readLock().lock();
        try {
            return map.getOrDefault(key, defaultValue);
        } finally {
            lock.readLock().unlock();
        }
    }
}
```

## Exercise 4: Fork-Join Framework

**Problem:**
Use the `ForkJoinPool` to parallelize a recursive sum of an integer array.

**Hint:** Extend `RecursiveTask<T>` and fork subtasks when the range exceeds a threshold.

```java
import java.util.concurrent.ForkJoinPool;
import java.util.concurrent.RecursiveTask;

class ParallelSum extends RecursiveTask<Integer> {
    private static final int THRESHOLD = 1000;
    private final int[] array;
    private final int start;
    private final int end;

    public ParallelSum(int[] array, int start, int end) {
        this.array = array;
        this.start = start;
        this.end = end;
    }

    @Override
    protected Integer compute() {
        if (end - start <= THRESHOLD) {
            int sum = 0;
            for (int i = start; i < end; i++) {
                sum += array[i];
            }
            return sum;
        }

        int mid = (start + end) / 2;
        ParallelSum left = new ParallelSum(array, start, mid);
        ParallelSum right = new ParallelSum(array, mid, end);
        left.fork();
        int rightResult = right.compute();
        int leftResult = left.join();
        return leftResult + rightResult;
    }
}

class ForkJoinDemo {
    public static int parallelSum(int[] array) {
        ForkJoinPool pool = new ForkJoinPool();
        return pool.invoke(new ParallelSum(array, 0, array.length));
    }
}
```

## Exercise 5: CompletableFuture Patterns

**Problem:**
Chain asynchronous operations using `CompletableFuture` to fetch, transform, and combine results.

**Hint:** Use `thenApply`, `thenCompose`, and `thenCombine` for chaining.

```java
import java.util.concurrent.CompletableFuture;

class AsyncPatterns {
    public static CompletableFuture<String> fetchUserId() {
        return CompletableFuture.supplyAsync(() -> "user-123");
    }

    public static CompletableFuture<String> fetchUserName(String userId) {
        return CompletableFuture.supplyAsync(() -> "User " + userId);
    }

    public static CompletableFuture<Integer> fetchUserScore(String userId) {
        return CompletableFuture.supplyAsync(() -> 95);
    }

    public static CompletableFuture<String> buildUserProfile() {
        return fetchUserId()
            .thenCompose(userId ->
                fetchUserName(userId).thenCombine(
                    fetchUserScore(userId),
                    (name, score) -> name + " - Score: " + score
                )
            );
    }
}
```

## Intuition

**Java concurrency is built into the language and standard library:** From synchronized blocks to ExecutorService to CompletableFuture, Java provides multiple levels of abstraction for concurrent programming. The JVM's memory model defines the rules for shared state access.

**Why it matters:** Modern applications must handle thousands of concurrent users. Understanding Java concurrency is essential for building responsive, scalable server applications.

**The key insight:** The java.util.concurrent package is almost always preferable to low-level synchronized blocks — it provides thread-safe collections, executors, and atomic operations that are easier to use correctly.

## Common Mistakes

**Using `Thread.stop()` or `Thread.suspend()`:** These methods are deprecated because they leave shared data in inconsistent states. Use interruption and cooperative cancellation instead. Always design threads to check for interruption and exit gracefully.

**Forgetting that `synchronized` is reentrant:** A thread can acquire the same monitor multiple times (reentrant locking). This is by design — it allows a synchronized method to call another synchronized method on the same object. But it means nested synchronized blocks dont cause deadlocks on the same monitor.

**Assuming `volatile` is sufficient for compound operations:** `volatile` ensures visibility (reads/writes go to main memory) but not atomicity. `i++` is not atomic even with volatile (read-modify-write). Use `AtomicInteger` or `synchronized` for compound operations.
