## OOP Practice

## Exercise 1: Observer Pattern

**Problem:**
Implement the Observer pattern where subjects notify observers of state changes.

**Hint:** Maintain a list of observers in the subject and call `update` on each when state changes.

```java
import java.util.ArrayList;
import java.util.List;

interface Observer {
    void update(String message);
}

class NewsAgency {
    private final List<Observer> observers = new ArrayList<>();
    private String news;

    public void addObserver(Observer observer) {
        observers.add(observer);
    }

    public void removeObserver(Observer observer) {
        observers.remove(observer);
    }

    public void setNews(String news) {
        this.news = news;
        notifyObservers();
    }

    private void notifyObservers() {
        for (Observer observer : observers) {
            observer.update(news);
        }
    }
}

class NewsChannel implements Observer {
    private final String name;

    public NewsChannel(String name) {
        this.name = name;
    }

    @Override
    public void update(String message) {
        System.out.println(name + " received: " + message);
    }
}
```

## Exercise 2: Factory Pattern

**Problem:**
Implement a Factory pattern that creates different shapes based on input.

**Hint:** Define a common interface, implement concrete classes, and a factory method to instantiate them.

```java
interface Shape {
    double area();
    String getType();
}

class Circle implements Shape {
    private final double radius;

    public Circle(double radius) {
        this.radius = radius;
    }

    @Override
    public double area() {
        return Math.PI * radius * radius;
    }

    @Override
    public String getType() {
        return "Circle";
    }
}

class Rectangle implements Shape {
    private final double width;
    private final double height;

    public Rectangle(double width, double height) {
        this.width = width;
        this.height = height;
    }

    @Override
    public double area() {
        return width * height;
    }

    @Override
    public String getType() {
        return "Rectangle";
    }
}

class ShapeFactory {
    public static Shape create(String type, double... dimensions) {
        return switch (type.toLowerCase()) {
            case "circle" -> new Circle(dimensions[0]);
            case "rectangle" -> new Rectangle(dimensions[0], dimensions[1]);
            default -> throw new IllegalArgumentException("Unknown shape: " + type);
        };
    }
}
```

## Exercise 3: Inheritance Hierarchy

**Problem:**
Design an animal hierarchy where `Animal` is the base class, with `Dog` and `Cat` subclasses overriding behavior.

**Hint:** Use `extends` and `@Override` annotations.

```java
abstract class Animal {
    protected final String name;

    public Animal(String name) {
        this.name = name;
    }

    public abstract String sound();

    public String describe() {
        return name + " says " + sound();
    }
}

class Dog extends Animal {
    public Dog(String name) {
        super(name);
    }

    @Override
    public String sound() {
        return "Woof";
    }

    public String fetch(String item) {
        return name + " fetches the " + item;
    }
}

class Cat extends Animal {
    public Cat(String name) {
        super(name);
    }

    @Override
    public String sound() {
        return "Meow";
    }

    public String scratch() {
        return name + " scratches the furniture";
    }
}
```

## Exercise 4: Interface Implementation

**Problem:**
Define a `Payable` interface and implement it in `Employee` and `Invoice` classes.

**Hint:** Interfaces define a contract; each implementing class provides its own logic for `getAmount`.

```java
interface Payable {
    double getAmount();
    String getDescription();
}

class Employee implements Payable {
    private final String name;
    private final double salary;

    public Employee(String name, double salary) {
        this.name = name;
        this.salary = salary;
    }

    @Override
    public double getAmount() {
        return salary;
    }

    @Override
    public String getDescription() {
        return "Salary for " + name;
    }
}

class Invoice implements Payable {
    private final String invoiceNumber;
    private final double amount;

    public Invoice(String invoiceNumber, double amount) {
        this.invoiceNumber = invoiceNumber;
        this.amount = amount;
    }

    @Override
    public double getAmount() {
        return amount;
    }

    @Override
    public String getDescription() {
        return "Invoice " + invoiceNumber;
    }
}
```

## Exercise 5: Generics

**Problem:**
Implement a generic `Pair<T, U>` class that holds two values and a generic `Box<T>` with a value and a map method.

**Hint:** Use type parameters with appropriate bounds where needed.

```java
class Pair<T, U> {
    private final T first;
    private final U second;

    public Pair(T first, U second) {
        this.first = first;
        this.second = second;
    }

    public T getFirst() {
        return first;
    }

    public U getSecond() {
        return second;
    }

    @Override
    public String toString() {
        return "(" + first + ", " + second + ")";
    }
}

class Box<T> {
    private T value;

    public Box(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }

    public void setValue(T value) {
        this.value = value;
    }

    public <U> Box<U> map(java.util.function.Function<T, U> mapper) {
        return new Box<>(mapper.apply(value));
    }
}
```

## Intuition

**Object-oriented programming models real-world entities as objects:** Objects combine data (fields) and behaviour (methods) into cohesive units. Encapsulation hides internal details, inheritance enables code reuse, and polymorphism allows flexible method dispatch.

**Why it matters:** OOP is the dominant paradigm for large-scale software development, enabling teams to build complex systems by decomposing them into manageable objects.

**The key insight:** Favor composition over inheritance — inheriting implementation creates tight coupling, while composing objects with interfaces creates flexible, testable code.

## Common Mistakes

**Confusing composition with inheritance:** Inheritance ("is-a" relationship) should only be used when the subclass is genuinely a subtype. Composition ("has-a" relationship) is preferred when the subclass merely uses functionality. Overusing inheritance creates fragile class hierarchies.

**Violating the Liskov Substitution Principle:** Subclasses must be substitutable for their parent classes without breaking correctness. If a Square extends Rectangle and overrides setWidth to also change height, code expecting Rectangle behavior will fail.

**Exposing internal state through getters:** If a class exposes mutable internal objects via getters, external code can modify internal state directly, breaking encapsulation. Return defensive copies or unmodifiable views of internal collections.
